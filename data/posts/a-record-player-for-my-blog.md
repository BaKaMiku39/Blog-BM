十一月的第一个凌晨，我在调一个圆角和一条描边的对齐，已经改到第几遍记不清了。

屏幕左边是编辑器，右边是浏览器，中间是安静得有点过分的房间。那时候突然很想让这个页面有点声音——不是「点一下才有」的声音，是「打开就在」的那种。

## 想要的是氛围，不是播放器

播放器这个功能，做起来只有两种结果：要么很吵，要么很没有存在感。

我想要的显然是后者：右下角一小块，有封面、有歌名、有一条细得几乎看不见的进度条。不滚页面的时候它几乎是透明的，只留下字和图标浮在插画上；往下滚一点点，它才悄悄变成一块磨砂玻璃；如果再滚到侧栏那个空位，它会停下来，变成一张白卡，乖乖待在那里。

三个状态，同一块地方，不位移、不缩放。这件事听起来简单，实际卡了我很久。

> 一开始我给它做了很漂亮的变形动画，结果每次吸附都像抽了一下。后来才发现问题根本不在动画：悬浮时是 430×120，吸附时是 280×138。尺寸都不一样，怎么缓动都会跳。

把两边的尺寸统一成 280×136 之后，动画只用负责一件事——让颜色在 0.3 秒里慢慢过渡。它忽然就顺了。

这件事让我记了很久：**动效救不了布局**。先让两个状态的位置和尺寸对得上，再谈曲线和时长。顺序反了，加多少缓动都像在补漏。

## 浏览器不让你自动播放

这是做这个功能撞上的第一面硬墙：没有用户交互，有声的自动播放一律被拒。

所以只能绕，绕成三段：

1. 进页面先直接试一次 `play()`。老访客、或者平时在这个站听过歌的人，多半能直接响。
2. 被拒了就挂一组一次性的监听，等他第一次点页面、按键盘、或者滑一下手机，再把声音接过来。
3. 如果他主动按了暂停，那就记住——`localStorage` 里写一个 `off`，以后不再自作主张。

最后一段大概长这样：

```ts
const KEY = 'bgm-autoplay';

export const wantsMusic = () => localStorage.getItem(KEY) !== 'off';

export function remember(playing: boolean) {
  localStorage.setItem(KEY, playing ? 'on' : 'off');
}
```

原则很简单：可以猜，但不能赖。猜错一次就够了，用户的手动选择永远比我的猜测优先。

## 顺手加的几个小地方

- **跨页面不断**：这是多页应用，跳一页就断会很扫兴。所以播放位置和进度都写进 `sessionStorage`，下一页接着放。
- **键盘能操作**：`←` / `→` 各退、进 5 秒，`Home` 回开头，`End` 到结尾。进度条也能点、能拖。
- **音量默认 0.7**：满音量在深夜有点吓人。

歌单是我自己的网易云歌单，十二首。一首一首试过能不能完整播放——这个接口没有登录状态，VIP 曲子只会返回三十秒的试听片，长度正好是 481115 字节。听起来很具体，但只有这种具体的数字能救命。

## 最后

现在凌晨一点多，页面右下角在放一首很轻的歌，进度条慢慢走。我其实没在写什么正经代码，只是在看那条进度条走。

一个博客需要背景音乐吗？不需要。但它让这个页面从「一个可以读的地方」，变成「一个待着还挺舒服的地方」。

霜降已经过了，立冬还有四天。

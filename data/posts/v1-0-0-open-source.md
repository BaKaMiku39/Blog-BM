凌晨一点半，我打开自己的博客，抽了一签，末吉。

签文是「慢一点也没关系，路还长」。然后右下角的音乐盒自己响了，放的是一首我从歌单里随手塞进去的曲子。

这两件事都毫无必要。没人会因为抽签多读一篇文章，也没人会在别人的博客上听歌。但它们是我做这个站的理由——一个只放文章的地方，和一份 PDF 没什么区别。

版本号推到 1.0.0 了，代码也开源了。这篇讲讲这些东西是怎么长出来的。

## 抽签：写给自己的功能

那支签挂在整个站最显眼的位置——顶栏下沿，一抬头就看见。

六支签，大吉、中吉、小吉、吉、末吉、平。每支配一句人话，不写「诸事不宜」那种。抽完顺手推一篇站里的随机文章：抽签和读文章本来没关系，但抽完总得有个去处。

限制是我自己定的：每天只能重抽三次，记在浏览器里，刷新还在；第一次打开时自动抽的那下不算次数，否则一进站就少一次。摇的时候签条绕绳结摆 4.2 度——再大就像在甩，不像在摇。

断网的时候它会说「没抓到签，网络开小差了」，不会弹一个红叉。

## 音乐盒：为了 12 首歌踩的一个坑

播放器在全站改了四版：白卡黑胶、和纸朱印、深色玻璃，到现在这版磨砂。

歌是我自己的网易云歌单，十二首。这里有个不看代码永远想不到的问题：我走的那个接口没有登录 cookie，**VIP 曲目只会返回 30 秒试听**，而那个试听文件的字节数固定是 481115。

所以每首歌都得单独验一遍：`curl` 拿响应头和总长度，是 `audio/mpeg` 且长度不等于 481115，才算真的能播。十二首挨个过。

播放器有三种状态，跟着你滚到哪：

- 刚进站：全透明，只有封面和字，压在首屏大图上
- 滚过一点点：变成磨砂，和顶栏同一层玻璃
- 滚到右栏那个空位：整张卡落进去，变成一张白卡

最后那下不跳，不是调出来的动画——悬浮时它的右边缘正好压在页面容器的侧栏边线上，槽位滚到位时两个矩形完全重合。没有位移、没有缩放，只有颜色在变。

还有一点：浏览器不允许「没有交互的自动播放」，所以它先试一次，被拒绝就等你第一次点页面；你主动按过暂停，它就记住了，以后不再自作主张。

## 名片：会看天气，也会看时间

左栏名片顶上有一条横幅，八张图：晴、云、雨、雪，白天夜里各一版。切明暗时两张图交叉淡入。

天气现在是写死的。不是懒——接口不稳的时候，一张「雨天」横幅配着窗外的大太阳，比不换图更尴尬。位置留着了，改一行就能接真的。

右边那张时间名片不换图，换状态：六点前是月亮，六点后是太阳；问候语七段，按小时走；后面那半句「今天也慢慢来」「记得吃晚饭」按半天轮换，**同一天里不会变**——不然每次刷新都换一句，像个坏掉的鸡汤生成器。

它现在还会每次刷新换一张插画。你打开时在插画上会看到一道光扫过去，那是我加的：让一张静态图看起来还活着。

## 界面的手感，是抠出来的

全站只有一套颜色，蓝打底，粉作强调，二十来个变量，暗色覆盖一份。切主题时不该有过渡——一开始我给它写了过渡，结果手机上卡成幻灯片。

查了很久，不在 JS，不在图片。真正的原因是我给 `background` 和 `box-shadow` 也加了 `transition`，这两个属性一变，后面那层模糊就要在每一帧重新算一遍。二十多张卡同时算，就卡住了。

把这两个属性从过渡里摘出去，只留边框颜色。硬切，反而比渐变舒服。

没配封面的文章，以前是一块灰渐变，看起来像图加载失败。现在是四套配色跟着分类走：技术笔记蓝、项目紫、动漫粉、碎碎念暖黄。同一个分类的两张也不一样——渐变角度和光斑位置是拿文章地址算了个哈希，只动这两项。

鼠标移上去会有道反光扫过封面。这个效果第一版是错的：我把光带撑到两倍宽再平移，结果可见的永远是渐变的中间段，整张图被一层白纱泡了一遍。涂成红色调试才看清，那其实是一块硬边矩形。后来改成窄带大位移，一秒多扫完，才像光。

带版本号的文章，封面左上角还挂着一枚御守：珐琅樱花扣、竖排纸牌、金绳和流苏。它只在你滚动页面的时候摆——静止时不动，动起来才像挂着的东西。

## 彩蛋

首页左上角的 logo，连着点五次，会从它的位置炸出一把花瓣。十二张精灵图，canvas 手写重力、旋转、淡出，没引库。

顺手把 logo 的点击接成了「回到顶部」，反正它本来也不跳转。

还有一个更隐蔽的：切到别的标签页再回来，标题会变成 `(´･ω･\`) 去哪了…`，回来的时候变回 `欢迎回来 (｡•̀ᴗ-)✧`。

## 后台和配置

后台在 `/admin`。浏览器里写 Markdown、看预览、传图、存草稿、发布。草稿和发布是分开的：保存只写文件，点发布才出现在首页——半成品不会被搜索引擎抓到。

配置全在 `.env`，按「运行 / 后台 / 站点 / 社交 / 音乐 / 开关」分了组。真正非填不可的只有三个，其余空着是「不显示」，不是「坏掉」——下一节展开。

## 配置：要动手的其实只有两处

`.env` 里三十来个变量，空着就跑不起来的只有三个：

- `ADMIN_PASSWORD` —— 后台密码，十六位以上随机串
- `SESSION_SECRET` —— 登录签名和访客去重都用它，`openssl rand -hex 32` 生成
- `PUBLIC_SITE_URL` —— 对外地址，**不要带结尾斜杠**

剩下的社交链接、备案号、每页篇数、四个功能开关，空着就是对应的东西不渲染。填完跑 `npm run config:check`，它按分组把当前生效值打出来（密码打码），必填项漏了直接退出码 1。这脚本没什么技术含量，但比自己 grep 一遍靠谱。

### 音乐盒：得自己架一个 Meting

播放器里没有一首音频文件，所有歌都走同一个地址：

```
/meting/api?server=netease&type=url&id=<歌曲ID>
```

`/meting` 不是这个项目的一部分。它是 [Meting](https://github.com/metowolf/MetingAPI) —— 把网易云、QQ、酷狗、百度的播放地址和歌词统一成同一个 URL 的中间层。想听歌就得自己起一个：

1. 起服务。Docker 最省事，官方镜像跑起来监听一个本地端口（我用的是 3030）
2. nginx 把 `/meting/` 转过去，注意 `proxy_pass` 结尾那个斜杠，它负责剥掉前缀：

```nginx
location /meting/ {
    proxy_pass http://127.0.0.1:3030/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

3. 本地开发没有 nginx，所以 `astro.config.mjs` 里留了一个 dev 专用代理。把 `METING_TARGET` 指向你的 Meting 服务，`npm run dev` 时音频和歌词就能取到。

`METING_SERVER` 决定默认音源，`netease / tencent / kugou / baidu` 四选一。歌单写在 `src/lib/playlist.ts`，换歌只改 id。

### 换歌之后必须验一遍

这条是我拿半首歌换来的经验：

```bash
curl -s -o /dev/null -D - -r 0-0 \
  'https://你的域名/meting/api?server=netease&type=url&id=<新ID>' \
  | grep -i 'content-type\|content-range'
```

要看到 `audio/mpeg`，并且 `content-range` 里的总字节数**不能是 481115**。这个数字是「30 秒试听」的固定长度——没有登录 cookie 的接口遇到 VIP 曲目只给这一段。播放器上看着一切正常，三十秒后自己停，你还以为是网络。

不想架这一套的话，把 `FEATURE_BGM=false` 一关，播放器整块不渲染，别的功能不受影响。

## 一些数字，包括一个白干的

- 服务器补了 gzip，CSS 从 302KB 压到 58KB
- 头像原图 1254×1254、107KB，实际只显示 76px；缩到 240px 后 9.6KB
- 手机首屏换了一张竖版插画，242KB 降到 61KB，取景是逐像素对过的
- 字体换成可变字重，字体文件从 202 个分片降到 101 个，请求数 20 降到 13——但**字体总字节从 609KB 涨到 663KB**，中文可变字重的分片更大，前后合计几乎没变

最后这条算是白干。不过知道为什么白干，比不知道强。

## 还没做好的

首屏还是一张写死的春景，本来想做四季轮换。封面还是「渐变加大字」，比灰块好，但离让人想点还差一张真图。访客统计是我自己写的，写完才发现，最起劲刷它的人是我自己。

这些慢慢来。代码已经放出去了，改起来总比藏着方便。
